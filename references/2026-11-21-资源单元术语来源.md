# 资源单元相关术语：出处与原文

## 结论（已确认采用）

| 语义 | 英文 | 中文 | 说明 |
| --- | --- | --- | --- |
| 个体：承载资源、可被单独调度的单位 | node / instance | 节点 / 实例 | 形态不敏感：物理机、虚拟机、容器、进程都能是"一个实例" |
| 增量：扩容时增加的那一份 | scale unit | 扩容单元 | 面向"扩容 = 增加 N 个单位"，不绑定形态 |
| 成组副本：一组需一起部署/伸缩的组件 | stamp / cell / service unit | — | 用于多租户、单元化部署语境 |

放弃的候选：`compute unit / 计算单元`（云计费语境里另有"计费单位"含义，易歧义）。

## 来源

### 1. Azure Well-Architected Framework — Reliability / scaling（scale unit 的定义性用法）

- URL: https://learn.microsoft.com/en-us/azure/well-architected/reliability/scaling
- 原文："Choose appropriate scale units. Base your scaling strategy on scale units, which are the logical grouping of components to scale together and the scale increments to use (like moving from one VM SKU to another)."
- 支撑：`scale unit` 是扩容策略的正式用词，含义同时包含"一起伸缩的组件"和"伸缩的步长"，即增量语义。

### 2. Azure Architecture Center — Deployment Stamps pattern（同义术语家族）

- URL: https://learn.microsoft.com/en-us/azure/architecture/patterns/deployment-stamp
- 原文："Deploy multiple independent copies of application components, including data stores, as a single group of resources. Each copy is called a stamp, or sometimes a service unit, scale unit, or cell."
- 原文："Deploy more stamps to scale the solution almost linearly, serve an increasing number of tenants…"
- 支撑：`stamp` / `service unit` / `scale unit` / `cell` 是同一概念在不同语境下的别名；扩容动作是"增加 stamp"，与线性扩展关联。

### 3. 阿里云开发者社区 — 单元化扩容（中文用法）

- URL: https://developer.aliyun.com/article/30668
- 原文（来自搜索引擎索引片段）："把 5 台机器定义为一个扩容单元，扩容单元通过 ROS 创建，随着流量增加，每次扩容增加一个扩容单元。"
- 核对状态：**未直接核对到正文**。该页为 JS 渲染，curl 直连返回阿里云风控/错误模板页（可见 "阿里云默认模板 / 系统自动生成 / 异常信息"），正文无法抓取。
- 支撑：中文工程实践中"扩容单元"对应 `scale unit`，且明确"一个单元 = 若干台机器"，即单元可以比单个个体粗。仅作中文译名佐证，不作定义出处。

### 4. Kubernetes Glossary — Node（个体术语，K8s 口径）

- URL: https://kubernetes.io/docs/reference/glossary/ （条目 `node`）
- 原文："A node is a worker machine in Kubernetes." / "A worker node may be a VM or physical machine, depending on the cluster."
- 支撑：`node` 的公认定义是"承载工作负载的机器"，覆盖物理机与虚拟机；不覆盖容器/进程粒度。

### 5. Kubernetes — Nodes 概念文档（同上，措辞更宽）

- URL: https://kubernetes.io/docs/concepts/architecture/nodes/
- 原文："A node may be a virtual or physical machine, depending on the cluster."
- 支撑：同 4；另说明 node 由控制面管理，是"被调度"的一方。

### 6. Wikipedia — Scalability（横向/纵向扩展的标准表述）

- URL: https://en.wikipedia.org/wiki/Scalability
- 原文："Scaling horizontally (out/in) means adding or removing nodes, such as adding a new computer to a distributed software application."
- 原文："Scaling vertically (up/down) means adding resources to (or removing resources from) a single node, typically involving the addition of CPUs, memory or storage to a single computer."
- 原文（引 ETSI NFV 术语）："scaling out/in is the ability to scale by adding/removing resource instances (e.g., virtual machine), whereas scaling up/down is the ability to scale by changing allocated resources (e.g., memory/CPU/storage capacity)."
- 另一处定义（引 Marc Brooker）："a system is scalable in the range where marginal cost of additional workload is nearly constant."
- 支撑：① `node` 是分布式系统文献里的默认个体单位；② 纵向扩展 = 给同一个 node 加 CPU/内存/存储，正好对应"资源可以再细化类型"；③ `resource instance` 是 NFV 语境下的同义个体单位；④ Brooker 的边际成本定义可支撑"技术问题→资源问题（成本问题）"的表述。

### 7. AWS — EC2 概念（instance 的定义，最贴合"资源可分项"）

- URL: https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/concepts.html
- 原文："An EC2 instance is a virtual server in the AWS Cloud. When you launch an EC2 instance, the instance type that you specify determines the hardware available to your instance. Each instance type offers a different balance of compute, memory, network, and storage resources."
- 支撑：把"实例"定义为承载 compute / memory / network / storage 四项资源的载体，且以"规格（instance type）"体现资源配比——与"计算单元的属性"这一用法高度一致。

### 8. Google Cloud — Compute Engine instances（个体术语的官方同义说明）

- URL: https://cloud.google.com/compute/docs/instances
- 原文："The terms Compute Engine instance, compute instance or instance are synonymous." / "Based on the machine type that you specify, an instance can be either a bare metal instance or a virtual machine (VM) instance…"
- 支撑：`instance` 在云厂商口径下同时覆盖裸金属与虚拟机，说明它是"资源载体"而非某种具体形态。
