# Scalability 最小 Demo 设计

## 建议方向

先演示一个无状态、CPU-bound 的服务：每个请求执行相同的可重复计算，不依赖数据库或队列。将同一程序作为多个进程实例运行，由压测客户端把固定负载分发给实例。

对比 1、2、4 个实例时，记录吞吐量、延迟分位数、错误率和 CPU 使用率。维持相同的请求内容、负载、机器资源和服务目标，观察增加实例如何缓解单实例的 CPU 瓶颈，以及机器 CPU 饱和后扩展收益如何下降。

## 设计原则

- 先只展示一个资源化动作：增加实例；不同时引入数据库、队列、缓存等变量。
- 不用固定 sleep 伪造耗时；用可重复的真实计算负载。
- 单机多进程只能展示到该机器可用 CPU 的上限；需要记录这个边界，避免把结果误读为线性扩展。
- 后续再分别为数据库、队列和 worker job 设计能暴露各自瓶颈的 Demo。
